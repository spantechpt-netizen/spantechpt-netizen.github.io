[2] تسجيل المشروع والأدوار (مرة واحدة لكل مشروع)

المسؤول: مهندس المكتب اللي هيطلع اللوحات (اسمه هو اللي هيتكتب في PREPARED / DESIGNED BY).

  1. لوحات التسليح ← مشروع جديد: الاسم (إنجليزي زي ما هيتكتب على اللوحة + عربي)، العميل، الاستشاري، المقاول، الموقع، الدولة. كود المشروع بيتولّد (P26-001) أو اكتبه.
  2. اختار افتراضيات المشروع (كلها بتتغير لكل إصدار من نافذة الإخراج): • نوع اللوحات: تصميم (Design) أو شوب (Shop). • حديد الرام: كل الحديد / حديد المصمم بس / قواعد المكتب بس. • شبكة البلاطة: سفلية بس أو علوية وسفلية. • تصميم الكمرات: حديد الرام / تصميم المكتب / الأكبر في القيمتين.
  3. زوّد الأدوار: كود الدور (B1, GF, L03…)، اسم الدور زي اللوحة، الزون، سمك الحوائط لو الرام مفيهوش، الترتيب.
  4. لو المشروع ليه جدول كمرات من مشروع سابق تحب توحّده معاه: تبويب جدول الكمرات ← استدعاء جدول مشروع سابق (قبل أول إصدار).

الناتج: مشروع بكوده، أدوار بأكوادها، ترقيم اللوحات جاهز (SPAN-DD-P26-001-B1-02).

[3] قبل الرفع: المخطط المرجعي وما لا يقرأه البرنامج من الملف

المسؤول: مهندس المكتب.

الخطوةمتىفين
المخطط المرجعي (DXF من المعماري / الإنشائي فيه المحاور والأعمدة وحدود البلاطة)لو المشروع ليه أكسات معمارية — وده الوضع الطبيعيصف الدور ← مخطط مرجعي ← ارفع الـ DXF ← التوفيق أوتوماتيك على الأعمدة (أو نقطة موحدة) ← احفظ
أعمدة مش مسيّفة بانشنج في الراملو تقرير البانشنج في الرام فيه أعمدة مش مسيّفةصف الدور ← تعديل ← الخانة (A/1, C/3 زي لوحة الفريمنج)
كمرات مش مسيّفة دفلكشن في الراملو تقرير الرام فيه كمرات مش مسيّفةنفس النافذة (BM1, BM3 زي لوحة الكمرات)
لو المشروع مالوش أكسات معمارية سيب المخطط المرجعي فاضي: البرنامج بيولّد شبكة من الأعمدة وبتتكتب ملاحظة إنها متولّدة.

[4] الرفع والإخراج (Run)

المسؤول: مهندس المكتب. الزمن: ثواني لدقيقة لكل دور.

  1. اطلع اللوحات (من صف الدور أو أعلى الصفحة) ← اختار النوع / حديد الرام / الشبكة / تصميم الكمرات ← المراجعة (فاضية = 00) ← وصف التعديل ← ملف الرام (أو أكتر من ملف مرة واحدة، كل ملف بيتربط بدوره) ← اطلع اللوحات.
  2. اللي بيحصل جوه البرنامج بالترتيب (تقدر تراجعه في REPORT.md): 1. قراءة الموديل: البلاطة والمش، السماكات، الأعمدة (المدوّرة بتتظبط)، الحوائط، الفتحات، الدروبات، البورستريب، الكابلات وبروفايلاتها، حديد الرام، الـ SSR، الأحمال بنوعها، المواد. 2. المناسيب والأجزاء: كل منسوب بلاطة منفصلة؛ أطول من 60 م يتقسم أجزاء (B1A, B1B). 3. المخطط المرجعي بيتوفّق على الموديل وبياخد مكان محاور / أعمدة / حدود الرام. 4. قواعد المكتب والتفاصيل العامة: حديد الأعمدة، الكمرات العابرة، المحيط، الفتحات، الدروبات (D4)، الحوائط (D2/D5)، البورستريب (D8)، D9، البانشنج (D12 من الـ SSR). 5. فحص البانشنج الاسترشادي لكل عمود + الأعمدة اللي كتبتها. 6. الكمرات: قراءة حديد الرام، تصميم المكتب (تحليل كمرة مستمرة + انحناء + قص + دفلكشن)، الاختيار حسب "تصميم الكمرات"، ثم التسييف على جدول الكمرات الموحّد للمشروع (النموذج الجديد بيتضاف، القديم مايتعدلش). 7. الكابلات: الماركات، الأطوال، التمديد، الكراسي، التقاطعات. 8. الحصر (حديد / خرسانة / كابلات) والتقرير. 9. اللوحات (كل لوحة بلوك / Xref + DXF + معاينة + CSV) والـ ZIP باسمه الرسمي.
  3. النتيجة في صفحة الإصدار: • الحالة مسودة ← كمّل على [6]. • الحالة متوقف — بانشنج / كمرات ← [5] الأول (مينفعش يتعتمد ولا يتقدم قبل القرار). • فشل ← الرسالة بتقول السبب (غالباً الملف مش .cpt بمش، أو مفيش بلاطة) ← ارجع لـ [1].

الناتج: إصدار برقم تسلسلي، لوحات مرقّمة، REPORT.md، quantities.json، punching.json، beams.json، ZIP.

[5] الإصدار متوقف: قرار المهندس المصمم

المسؤول: المهندس المصمم (بيتسجل اسمه والتاريخ مع القرار، وبيتكتب على اللوحات لو تخطّى).

التنبيهالسببالقرارات المتاحةاللي بيحصل بعد القرار
تنبيه بانشنج (كارت أحمر بجدول الأعمدة: الموقع، مساحة التوزيع، Vu، vu/φvc، التقدير)عمود كتبته مش مسيّف في الرام، أو التقدير الاسترشادي بيقول مش مسيّف حتى بالكاناتهزوّد سمك الدروب / البلاطة → يفضل متوقف لحد موديل جديد · مسيّف في تقرير الرام (إقرار) → إعادة إخراج من غير PS · أتخطى على مسؤوليتي (إقرار + سبب) → إعادة إخراج بتسليح بانشنج PS عند الأعمدة دي مكتوب عليه على مسؤولية المهندس باسمه والتاريخالإصدار القديم "ملغي (استُبدل)"، الجديد بنفس المراجعة، القرار محفوظ على الدور للإصدارات الجاية
تنبيه كمرات (جدول القوى: البحور، عرض التحميل، wu، Mu±، Vu، حديد الرام / تصميم المكتب / المرسوم، الدفلكشن)كمرة مش مسيّفة دفلكشن (أو قطاعها مش شايل المومنت / الشير) في تصميم المكتب، أو كتبتها مش مسيّفة في الرامهزوّد عمق الكمرة → متوقف لحد موديل جديد · مسيّفة في تقرير الرام (إقرار) · أتخطى على مسؤوليتي (إقرار + سبب) → مكتوب على لوحة الكمرات وعند الكمرة NOT PASSING (DEFLECTION) باسمه والتاريخنفس الشيء
الأعمدة والكمرات اللي "محتاجة مراجعة" (تحذير أصفر) مابتوقفش الإصدار: راجعها في تقرير الرام وبس. تقرير الرام هو المرجع دايماً، والتقدير بيقول لك تبص فين.

[6] مراجعة الإخراج قبل ما يتقدم لأي حد

المسؤول: مهندس المكتب ثم المهندس المصمم (مراجعة).

  1. الافتراضات (في صفحة الإصدار وعلى كل لوحة): كل سطر معناه حاجة اتفرضت — الجدول في الدليل التفصيلي §5.1 بيقول معنى كل سطر وحلّه. اللي يخص الموديل (حائط اتصنف غلط، سمك مفروض، عمود بره البلاطة) يرجع للمصمم ← ملف معدّل ← إصدار جديد.
  2. اللي اتقرا من الموديل: عدد الأعمدة / الحوائط / الفتحات / الكابلات / الحديد — قارنه بالرام بنظرة.
  3. اللوحات (معاينة أو DXF): الفريمنج ← السفلي ← العلوي ← البانشنج ← الكابلات ← الكمرات. Checklist اللوحات في الدليل التفصيلي §5.2 (الأطوال، الأرجل والـ U، مفيش سيخ داخل فتحة، الكتابة في اتجاهها، كل سيخ له بعد ونقطة).
  4. الجداول (CSV) = اللوحات.
  5. تعديل يدوي؟ زر عدّل التسليح (المحرر): حذف / تطويل / تغيير مواصفة / إضافة سيخ ← احفظ ← أعد الإخراج = إصدار جديد بمراجعة أعلى والتعديلات محفوظة على الدور وبتتطبق تاني على أي إصدار بعده.
  6. الأوتوكاد: افتح الـ DXF، استبدل المحاور المولّدة بالمعمارية لو مفيش مخطط مرجعي، وراجع البلوكات (الدليل §6).

الناتج: إصدار مراجَع (لسه مسودة).

[7] (اختياري) تصميم الكمرات عبر الرام

المسؤول: مهندس المكتب يجهّز، المهندس المصمم يحسب في الرام.

  1. من صفحة الإصدار: جهّز موديل الرام بشرائح الكمرات ← حمّل الموديل (.cpt). (البرنامج مسح كل الـ design strips وحط شريحة على سنتر كل بحر كمرة + splitter على حرفيها.)
  2. في الرام: افتح الموديل ← Calc All ← احفظ.
  3. ارفع الموديل المحسوب إصدار جديد لنفس الدور (نفس [4]).
  4. الكمرات بتطلع نماذج (B1, B2 …) مكتوبة على كل كمرة مع قطاعها، وجدول التسليح والقطاعات على لوحة الكمرات (07 تصميم / 09 شوب)، وبتتسيّف على جدول الكمرات الموحّد للمشروع: النموذج الموجود بيتاخد زي ما هو (أخف نموذج بيسيّفها)، الجديد بيتضاف بنجمة *.
  5. اختيار تصميم الكمرات بيحدد حديد اللوحة: حديد الرام، تصميم المكتب (من التحليل)، أو الأتقل في الاتنين مجموعة بمجموعة. القوى وحديد الاتنين في صفحة الإصدار وREPORT.md.

[8] الشوب درونج (نفس الملف)

المسؤول: مهندس المكتب.

اطلع اللوحات من نفس ملف الرام بنوع شوب (Shop): فريمنج، حديد سفلي / علوي (+ الإضافي من الرام 02A / 03A)، U-bars، الفتحات، الكابلات لكل اتجاه (07A / 07B: التاجات الخمس خانات، الكراسي كل متر، التمديد، جدول الكراسي، الداكت، الكميات، سجل الشد) والتقاطعات (07C: مين فوق ومين تحت، التصادمات)، البانشنج، الكمرات. الشوب بياخد نفس القرارات والمخطط المرجعي والجدول الموحّد.

[9] الاعتماد

المسؤول: مهندس المكتب يجهّز، المسؤول عن التسليم يقدّم.

  1. اعتمد كإصدار صادر في صفحة الإصدار (الإصدار الصادر الأقدم لنفس الدور والنوع بيبقى ملغي). ماينفعش لو الحالة "متوقف".
  2. تبويب طلبات الاعتماد ← طلب اعتماد جديد: علّم الإصدارات (أو لوحات مختارة)، الجهة والعناية والغرض ← الرقم بيتولّد (SPAN-SUB-P26-001-001) والنموذج بيفتح للطباعة / PDF بأرقام اللوحات وعناوينها ومراجعاتها زي كارت اللوحة.
  3. رد الاستشاري: غيّر الحالة (مُقدَّم ← معتمد / بملاحظات / يُعاد التقديم / مرفوض) مع التاريخ والملاحظات.
  4. إعادة تقديم: عدّل ← إصدار جديد ← طلب اعتماد جديد بيكتب "يحل محل" المراجعة والطلب القديم أوتوماتيك.

[10] الحصر ودراسة التكلفة

تبويب الحصر والتكلفة: الحديد (علوي / سفلي / شبكة / حسب القطر)، الخرسانة (صافي، دروبات، كمرات، شدات)، الكابلات (كابلات، خيوط، أطوال قص، مراسي، داكت) — لكل دور من إصداره الصادر (أو آخر مسودة) — ودراسة التكلفة بأسعار الوحدة من الإعدادات مع تجربة أسعار من الشاشة. كل جدول له CSV.
